name: architecture-invariants
description: Review-time invariants for Custodes: credentials only in the broker, policy widening needs an ADR, readonly agents (ADR 0009) have no policy entry, per-agent read resource allow-list (ADR 0010), specialist delegation pattern
metadata:
  type: project
---

- Agents never hold GitHub or e-mail credentials; only `workers/github-broker` does. Any PR that adds a token binding to `workers/agents` is a finding.
- Policy file: `workers/github-broker/policy/policy.json`. Widening `repos`, `actions`, `rateLimitPerHour`, or (since ADR 0010) `reads.<agent>.resources` needs an ADR reference in the PR.
- ADR 0009 (2026-09-28): `readonly` agent mode. A readonly agent has NO `agents` policy entry (broker answers `unknown_agent`), `CustodesAgent.act()` throws, and `evaluatePolicy` denies even if an entry is added. Reads go through the broker's GET-only `/v1/read` with `PAT_READONLY` (the earlier "unauthenticated client in the agents Worker" exception is gone).
- ADR 0010 (2026-10-01): `ReadPolicy.resources` is a required per-agent allow-list; a new `ReadResource` enum value grants nothing until listed. Numbered resources need `number` (≤1e6), `cheatsheet` needs `file` matching `CheatSheetFile` (no `/`, no leading dot). The broker builds every path (`buildReadPath`); agents never pass paths. Check that each agent's grant matches what its reader methods actually call.
- Specialist pattern (ADR 0010): triage hands specialists **ids only** (`SpecialistJob = {issue, issueUpdatedAt}`) over DO stub RPC; specialists re-read under their own agent id and re-validate args with zod; triage re-validates results on receipt. Cost bound is `MAX_JOBS_PER_DAY` per specialist in server-owned state.
- ADR 0012 (2026-10-15): repo comes only from the DO instance name via `workers/agents/src/instances.ts` (`owasp-cheatsheetseries`, `custodes-sandbox`). Sandbox-only behaviour (on-demand POST runs, pr-gate grace skip, maintainers gated) must be keyed on `instanceOf(this.name).sandbox`, never on a request field; crons hard-code `OWASP_INSTANCE`. Kill switch and broker rate limit are per agent id, so shared across instances (accepted). Check new agents/routes keep this.
- ADR 0013 (proposed 2026-10-20): `reads.pr-gate` gains `comments` for the maintainer-agreement check. Verified then via the public API: in OWASP/CheatSheetSeries, `mackowski` (operator AND the pr-gate posting account) is COLLABORATOR, `randomstuff`/`kwwall` COLLABORATOR, `jmanico` MEMBER, with no bot comments in the last 100. MEMBER means any (public) OWASP org member, not only this project's maintainers. Agent comments are told apart from the operator's own comments only by the broker trailer (`Custodes-Agent:`).
- ADR 0014 (proposed 2026-10-26, PR #64): CI reaches Anthropic only via WIF (GitHub OIDC -> /v1/oauth/token). Verified then: repo OIDC sub uses `use_immutable_subject` (`repo:mackowski@35339942/custodes@1387781101`), repo public, `ci` environment has no branch policy, `ANTHROPIC_API_KEY` repo secret still present (removal is an operator step). Console rule config (CEL events, service-account role, workspace; no separate CI spend limit by operator choice 2026-10-26) is outside the repo and outside Terraform: ask for it, never assume. In reviews flag any job with `id-token: write` that also runs `pnpm install`/third-party actions, and any new `pull_request_target`/`workflow_run`/`issue_comment` trigger next to `id-token: write`. claude-code-action (pinned f27be6b) writes the OIDC JWT and cached access token under `$RUNNER_TEMP/claude-workload-identity` during each step; the review model's unrestricted `Read` plus `gh pr comment` (unmasked channel) can reach them.
- ADR 0006 amendment (2026-10-26, branch feat/pr-gate-webhooks): agents Worker `queue()` routes `pull_request` opened/reopened on `INSTANCES` repos to `PrGateAgent.notify(updatedAt)` (timing only, `wakeAt` clamps) via `workers/agents/src/dispatch.ts`. Gateway HMAC covers the body only: `x-github-event`/`x-github-delivery` are unsigned and there is no replay dedupe, one webhook secret for all repos. Any webhook-triggered path must stay timing-only.
- ADR 0015 (2026-10-26, branch feat/clef-shadow): Cloudflare Clef (`@cf/cloudflare/clef`, Workers AI) is a SHADOW of Jev in pr-gate via `shadowed()` in `pr-gate/shadow.ts` (Promise.all of try/catch-wrapped calls, Jev's result/error returned unchanged, Clef 10 s timeout). The agents Worker now has an `AI` binding visible to EVERY agent; ClefClient requires a gateway id, but a raw `env.AI.run()` without `gateway` skips the `custodes` gateway (logs, 60 rpm limit) and the "one gateway" unit test only scans https URLs in top-level `packages/llm/src/*.ts`. Ground truth (`human_verdict`) partly comes from author-controllable events (author self-close = `closed`). Any future "agreement" mode that lets Clef influence closes needs its own ADR and review: check Clef stays out of `decide()` and that ground truth is not author-controlled. CI secret `CF_WORKERS_AI_EVAL_TOKEN` (Workers AI Read+Edit) lives in the evals step next to an unpinned-transitive `pnpm dlx promptfoo`.
- ADR 0017 (2026-10-29, branch feat/cheatsheet-review-broker): `cheatsheet-review` is the second write agent, `hotl` from day one (explicit departure from CLAUDE.md invariant 3 / ADR 0004, justified by "operator's label is the per-run decision"; the broker cannot see the label, so hotl = any act() under that id posts). Policy: `pr.review.inline` (no APPROVE in schema) + `issue.label.remove`, sandbox only, enforced by `workers/agents/test/sandbox.test.ts`; widening to OWASP is a separate reviewed PR. It is the FIRST agent ever granted `issue.label.remove`; found in review and fixed in the same PR: label `.`/`..` (URL dot segments, `.` -> DELETE `/labels/` = remove-all) are refused by the schema, and the new policy `labels` allow-list limits it to `custodes_cheatsheet_review`. Check every future label grant sets `labels`. Reads `pull` and `pull_file_at_ref` (agent supplies a `CheatSheetPath` + 40-hex `ref`; broker does not check the ref is the PR head). Trigger actor is `mackowski`, the same account that owns the classic PATs: never grant `issue.label.add` to an agent whose PAT is on the trigger actor's account. Inline comment bodies carry no `Custodes-Agent` trailer (only the review body does).
- ADR 0017 amendment (2026-10-30, branch feat/cheatsheet-review-lineup): the lineup comes from a one-off hand-run benchmark (`workers/agents/scripts/benchmark/`, data in git-ignored `.bench/`, never in CI; it calls api.github.com directly with an optional local `GITHUB_TOKEN`, GET only, outside `src`). `ChatRequest.hosts` → OpenRouter `provider.only` + `allow_fallbacks: false`, added next to `data_collection: 'deny'` (filters intersect; empty intersection fails closed into the breach → mail-only path). `invariantBreach` (lineup.ts) is the runtime multi-model check: it only covers security voices vs judge, so judge==practicality model (Sonnet fallback) is allowed. Check any new `hosts` entry is a variant slug (`x/fp8`): a bare slug like `together` matches every variant. Fixed in a32f99d (hosts now nebius/parasail/crusoe `/fp8`); `render.ts` `DIMENSION_ROLES` deliberately omits Links & sources so it is never forced to NOT RUN (deterministic HTTP/anchor checks still run and can block). Retention guarantee is `data_collection: 'deny'` (not `zdr`), not the host list.
- ADR 0017 amendment 2026-10-30 (commit 0f773b3, approval links): the broker has two entrypoints. The default one (bound by agents) has act, read and POST /v1/approvals. `BrokerAdmin` (WorkerEntrypoint, bound only by the gateway via `entrypoint`) has decide, list, attestations and keys. The only thing keeping agents off BrokerAdmin is wrangler config; `packages/core/test/bindings.test.ts` pins it; since 59b7595 it loops over every dir in `workers/`, fails if any wrangler.jsonc has `env`, and also pins the AUDIT D1 (by database_id) to the broker. Still blind to KV/R2/queues and to Workers outside `workers/`. The approval HMAC key is generated inside the Keyring DO (`approval_key` table); `APPROVAL_TOKEN_SECRET` is gone from code and CI, but wrangler deploy does not delete it from deployed Workers. On approval the broker itself runs the stored `request_json.request` through `act()`. `requiresApprovalOn` is a per-repo approval list (narrowing, not widening). Follow-up 2aaa0cd verified 2026-10-30: agent `/v1/act` refuses `approvalId` (so `decideApproval` is the ONLY spender of an approval), decideApproval consumes in `finally` (59b7595; act.ts also consumes on the success path), `act()` checks expiry, `decide` reads `meta.changes`, approve-by-id removed in CLI/gateway/broker (reject only), link page shows the hash-checked `request.action`, `createApproval` refuses halted agents and caps 20 pending per agent (soft, check-then-insert). Accepted decision: an approval whose mail failed can never be approved (no CLI approve); operator rejects and relabels. Re-check if any new caller of `act()` with `approvalId` appears.
- Sync script `scripts/sync-agent-secrets.sh` reads `${!var}` for every policy `tokenBinding`, and the schema allows any `^[A-Z][A-Z0-9_]*$`, so a policy naming `CLOUDFLARE_API_TOKEN` could copy the deploy token into Secrets Store. Fixed 2026-10-29: schema requires `^PAT_[A-Z0-9_]+$` and the script refuses other names.
- E-mail from agents is bounded by `send_email.allowed_destination_addresses` in `workers/agents/wrangler.jsonc`; the `to` must come from a var, never from model or issue data. Widening the list is a reviewed PR.

**Why:** These are the load-bearing controls; the threat model (docs/architecture/threat-model.md) accepts that agents in one Worker share a trust domain, so the broker policy is the real blast-radius limit.

**How to apply:** Check them first in every review (authority category). Treat a readonly agent gaining a `tokenBinding`, an `agents` policy entry, or a new `resources` grant without an ADR as a finding. See [[agents-sdk-trust-surface]] for what "RPC" means in trust terms and [[email-rendering-pattern]] for the digest checks.
