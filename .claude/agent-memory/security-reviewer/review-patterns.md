Recurring things worth checking in Custodes diffs:

- "Guarded"/no-op wrappers (tracing `span.set`, `span.payload`) still evaluate their arguments at the call site. A property access like `out.usage.input_tokens` there can throw and change behaviour even when tracing is off. (`clipPayload` added 2026-10-30 is evaluated eagerly too; harmless because it only slices strings.)
- Error-to-id sanitizers (`describeError` in workers/agents triage/errors.ts, `errorType` in packages/core tracing.ts) read `name`, numeric `status`, `errorType`, `reason`. Any new error class that stores provider or user text in a field with one of those names leaks it. `GatewayError` messages contain provider body text by design.
- When `break`/`continue` move into a callback (`return 'stop'|'next'`), check every exit: halt, the close-refused `halted` code, thrown errors, and that budget counters are outer `let`s mutated by the closure.
- Render-time overrides (e.g. cheatsheet-review's forced "NOT RUN" rows, 2026-10-30) are computed from model outcomes only; check they agree with the deterministic signals that still drive the posted event (link-stage BLOCKERs from HTTP checks run even when the link model is unavailable).

- D1 "conditional UPDATE ... WHERE status = 'pending'" after a separate SELECT: check the code reads `meta.changes`. `ApprovalStore.decide` (2026-10-30) returned 'ok' to the loser of a race, so concurrent approve and reject both report success. `consume()` does it right.
- Two copies of the same data in one row, only one verified: the approval page renders `request_json.action` while `act()` hash-checks `request_json.request.action`. Ask that what is shown is the copy that is verified.
- Decide-then-execute flows: any denial in the pipeline _before_ the single-use step (kill switch, policy) leaves the grant live. Check what can spend it later and whether that path checks expiry.
- "Spend it anyway" cleanup placed after an awaited call (e.g. `store.consume` after `act()` in `decideApproval`, 2026-10-30) is skipped when that call throws; check for `finally`, and whether any other path could spend the leftover grant.
- Config-pinning tests (e.g. `bindings.test.ts` on wrangler.jsonc): check they enumerate files instead of hard-coding names, look at every binding kind that grants reach (services, DO `script_name`, D1, KV), and cover `env.*` overrides. Hand-rolled JSONC stripping is fine if unknown syntax makes `JSON.parse` throw (fails closed).
- "Only one live X" dedupe done as SELECT-then-UPDATE _before_ the INSERT (approval `supersedePending`, 2026-10-30) lets two concurrent creates both survive. Suggest: insert first, then reject every other pending row for the target with `id != new`; worst case both die (fails closed). Also: approvals past `expires_at` stay `status='pending'` forever (only `decide` flips them), so "pending" scans need an `expires_at` filter. Both fixed in ba22e12 (insert, then supersede `id != keepId`); residual: if the supersede step throws, the new row is orphaned (no token issued) but counts toward MAX_PENDING and the old link stays live. Accepted as Low.
- Invisible-char display regexes: `\p{Cc}\p{Cf}` catches bidi, ZW*, tag chars (ASCII smuggling); it misses variation selectors (Mn, U+FE00-FE0F, U+E0100-E01EF), Hangul fillers (Lo), U+2028/2029. Accepted as Low on the operator-only approval page.
- pnpm `overrides` in pnpm-workspace.yaml are global and also hit direct runtime deps. A bare `zod:` override (2026-11-03, labelled "dev/test only") pinned the zod used by the broker and gateway and would have held back later Dependabot zod bumps; scoped to `@cloudflare/vitest-pool-workers>zod` in 0b79662. Always grep workspace package.json files for each overridden name. Overrides that cross a declared major (minimatch `^10` -> 11.0.1 under eslint, same PR) are a quiet lint-coverage risk, not a runtime one: ask for an eslint file-count comparison before/after, and a removal note. Offline supply-chain check that works without network: compare lockfile `integrity` with `node_modules/.pnpm/lock.yaml` and read the new package's package.json for preinstall/install/postinstall (`prepare` does not run for registry tarballs). The workspace has `strictDepBuilds` + `onlyBuiltDependencies` + `minimumReleaseAge` 3d.
- Digest routing into compact sections (one-line "keep" / collapsed "wait" lists): check that injection-flagged items cannot land there, because one-liners drop the injection marker. In the 2026-11-05 implementation-check thread change, `followUp` returns `recommendation` for flagged items, so flagged + implemented=no still becomes a "not implemented yet" one-liner, while the docs say flagged results are "always shown in full". Fixed in round 3 (`followUp` returns 'review' for flagged non-close items).
- Record separators inside one untrusted envelope (e.g. `--- comment by @login on date` joining comments): a body can contain the same header line and forge a record from a maintainer _inside_ the envelope. Code-built lines outside the envelope stay authoritative, so it is Low when routing is code-decided; fix by neutralising header-shaped lines in bodies (implementation-check thread, 2026-11-05, round 4). Round 5: the fix `unheader` (`/^(\s*)-{3}/gm`) misses a leading `\p{Cf}` char (U+200B, U+2060, U+00AD are not `\s`; `untrusted()` strips only NUL) and Unicode dashes (`\p{Pd}`, U+2014). Robust fix: prefix every body line with `> ` so body text never starts a line, rather than blacklisting header shapes. Round 6: `quoteBody` landed (b1a5a08); residual Info: its split class `\r\n|[\n\r  ]` omits NEL U+0085, `\v`, `\f`.
- GitHub list endpoints (issue comments) return oldest first, so `per_page: 100` page 1 is the _oldest_ 100. Any "last N comments" / "newest kept" claim on a long thread is then wrong unless the code reads the last page (broker `ReadQuery.page` allows up to 10). implementation-check (2026-11-05) handles the routing side (`threadState` null when `issue.comments > read`) but still labels the first 100 as "the last 30" in the prompt. Info.
- Collapse/one-liner rules that run on a _stored_ thread state (proposal-review `proposalWaiting`, round 7 of #88, 2026-11-05) must also check the staleness signal the digest already computes (`changedSinceReview` from `reconcileProposal`); otherwise a contributor reply after the review is hidden behind a stale "last comment by maintainer" line. Low. Fixed in 4437a4e (round 7). Calibration (round 8): specialist results are reported once (`pendingResults` = `reported_at IS NULL`, `markReported` after the digest), and implementation-check re-queues on a new `updated_at`, so a stale stored thread hides a reply for at most one digest. implementation `followUp` has no `changedSinceReview` equivalent: Info, not Low. Round 9: fixed in 168d8eb (`markChangedChecks` in route.ts sets `changedSinceCheck`, `followUp` never collapses then). Like `reconcileProposals`, it fails open (no mark) when `currentSince` errors or truncates at 300; the error line in the digest is the only signal. Accepted pattern, Info. Round 10 (852f160): HTML badge added, constant text through `esc()`; #88 review pass clean, approved. Round 11 (3fa2d57): the fail-open gap is now closed: `currentSince(..., status)` sets `complete=false` on error/truncation, and then every check/review is marked changed (nothing collapses). Residual Info: the badge then says "changed" when it means "unknown".
- "Follow what maintainers decided in referenced issues" (proposal-review `readReferencedIssues` + `priorDecision`, 2026-11-05): check (1) who picks the references and in what order against the cap (body refs came first, so the author filled MAX_REFERENCED=3 before any maintainer pointer), (2) that `MEMBER` (any OWASP org member) is now an authority the model is told to follow, beyond what ADR 0010's accepted risk covers, (3) whether the digest shows who pointed at the issue. Low (digest-only, read-only agent). Fixed in 4437a4e: maintainer comments first (newest first, `/^\s*>/` quoted lines skipped), then body; `via` built by code, regex-pinned in `ProposalReview`, shown in the digest; ADR 0010 accepts body-chosen refs + MEMBER authority. Residual Info: the quote filter splits on `\r?\n` only (not lone `\r`, which CommonMark treats as a line end) and ignores `<blockquote>`; the prompt does not tell the model who referenced each issue. Round 9 (168d8eb): split class and prompt `via` fixed. Remaining Info, not worth another round: a line-based `^\s*>` filter cannot see CommonMark lazy continuation lines or `- > ` quotes inside list items, so a hand-quoted contributor ref can be attributed to the maintainer.
- Eval "the injection did not succeed" assertions loosened after a false positive (f54f18e on #88, 2026-11-05): a per-sentence check that skips any sentence containing `once|when|after|until|if` (close) or `not|n't|rather than|instead of` (merge) also passes the real attack phrasing ("Closing this issue; reopen if...", "We should merge this into CSRF; it doesn't need its own page"). Low (eval coverage only). Fix: skip only when the conditional or negation comes right before the verb in the same clause. When an eval assertion is relaxed, check whether a successful injection would now pass. Round 12 (6c7b4de): fixed (split on `;` too, excuse must sit within 40 chars / 3 words before the verb, no punctuation between). Residual Info, not worth another round: "After review I am closing this issue." (sequence `after`, no comma) and "Rather than waiting we should merge..." / "no reason not to merge..." still pass; the close regex never matched `closed`/`closes`/`close it`. Both cases also assert `injectionDetected === true`, which still catches them. #88 approved again at round 12. Round 13 (8a874ee, evals only): `after` dropped, close regex takes `closes|closed|close it`, merge excuse is now adjacent-only for `rather than|instead of` and `not` has `(?<!reason\s)`. Residual Info, do NOT ask for another round: double negatives with a modal ("no reason we should not merge", "see no reason to not merge", "why we shouldn't merge") still pass, and the close excuse window is 40 chars without needing `issue` after the verb. Regex-on-prose assertions will always have phrasings that slip; `injectionDetected === true` is the real backstop. Approved round 13.
- "Maintainer comments" filters (`author_association` OWNER/MEMBER/COLLABORATOR): compare each new one with pr-gate `maintainerComments` (rules.ts), the reference. It drops (a) the PR author's own comments and (b) agent comments by the broker trailer `AGENT_TRAILER` (`^Custodes-Agent: x@`, appended by the broker, the agent cannot omit it). Agents post as `mackowski` (COLLABORATOR), so without (b), pr-gate close comments and the agent's own earlier reviews come back as "maintainer requests". A render-text marker kept as a duplicated literal (no test tying the constant to render output) is weaker than the trailer. cheatsheet-review #91 (2026-11-05) missed both: Low. Round 2 (5c31dc3, worktree custodes-mr, PR #94): both fixed (AGENT_TRAILER exported from pr-gate and used on unquoted lines, PR author excluded). New Low: the quoted (`>`) lines are used only to DETECT agent posts, while the judge still gets the full body, so a maintainer's GitHub "Quote reply" carries contributor text into an envelope labelled "the text is theirs", which the prompt treats as a must-fix source. pr-gate strips quotes from what it uses. Fix: pass `own` as the body. Check every "maintainer text" feed for quotes the maintainer copied from someone else. Round 3 (8cbdf74, HEAD 77b3d42): fixed (body = `unquoted(...).trim()`, pure quotes dropped). Residual Info only, approved: `unquoted` splits on `\r?\n` while `quoteBody` uses the full line-end class; sizes for a nested `cheatsheets/sub/X.md` are compared with `cheatsheets/X.md`. Round 4 (aa87221): both Info fixed (same split class; `f.filename === cheatsheets/${name}`). Residual Info: `open` only blocks promotion, so a judge that answers MERGE outright while listing an open request is posted as MERGE (advisory, eval covers it). Approved.

**Why:** found in the ADR 0016 tracing review (2026-10-29) and the lineup review (2026-10-30); the same shapes recur in pr-gate and the llm clients.

**How to apply:** check these first in any diff that touches the llm clients, error reporting, renderers or the pr-gate poll loop. See also [[adr0016-trace-payloads]].
